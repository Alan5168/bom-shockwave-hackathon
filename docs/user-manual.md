# 缺料冲击推演器｜用户手册

版本：v0.1  
适用对象：计划员、采购、生产、仓库负责人，以及黑客松评委

## 1. 这是什么

缺料冲击推演器把中小工厂常见的“跨部门 Excel 考古”压缩成一次浏览器推演：

1. 导入多层 BOM、库存、到货计划和产线周计划；
2. 选择一颗风险物料；
3. 系统展开 where-used，按到货批次做净算与分配；
4. 看它打到哪些成品、工单、产线和客户；
5. 修改一个到货日期，整张图即时重算；
6. 比较五类通用动作的必要参数与剩余窗口；
7. 把选定动作拆成采购、产线、仓库、计划、研发、销售、物流七类指令。

应用没有后端、数据库、账号、API key 或运行时 LLM。CSV 文件只进入当前浏览器内存，
刷新或关闭页面后消失。

## 2. 最快体验：一键演示

1. 打开首页，点击“**一键引爆合成工厂**”。
2. 系统程序生成 24 个成品、8 个二级模组、共享阻容件、库存、两批电容到货和 24 张工单。
3. 事件焦点默认是 `CAP-104-50V`，首批采购单延期到 2026-08-19。
4. 顶部先看净缺口、受击成品、断线日和延期代价。
5. 中间冲击图显示“物料 → 成品工单 → 产线 → 客户”传播。
6. 右侧 Playbook 比较催交、挪料、客户改承诺、替代料、提良率。
7. 页面底部复制七张部门指令，或导出完整事件 JSON。

演示数据中的公司和客户均标有“（合成）”。所有料号、工单、日期、数量和采购单均为
程序化虚构，不来自任何原任职公司。

## 3. 改一个到货日期

工作台右上“首批到货日”默认是 `2026-08-19`。把它改成 `2026-08-05`：

- 到货批次立即重新进入分配池；
- 每个工单的准时可得数量与完工日重新计算；
- 净缺口、受击产品、延期成本、冲击图和产线 delta 同步刷新；
- Playbook 的“需拉进几天”和选项排序同步变化；
- 七张部门指令使用新日期与新数量重新生成。

这一步不发送网络请求，也没有“重新提交”按钮。

## 4. 导入自己的四张 CSV

点击工作台右上“**数据台**”，按顺序导入：

### BOM

必需字段：父项、子项、用量。可选：损耗率。

```csv
父项,子项,单耗
FG-001,ASM-01,1
ASM-01,CAP-104-50V,3
```

### 库存

必需字段：料号、现有量。可选：预留/占用、库位。

```csv
料号,现有量,占用,库位
CAP-104-50V,620 pcs,80,A01-03
```

### 到货计划

必需字段：料号、数量、到货日期。可选：记录号、供应商、采购单。

```csv
到货计划号,物料编码,数量,到货日期,供应商,采购订单
SUP-01,CAP-104-50V,"1,600件",2026年8月19日,示例供应商,PO-001
```

### 周计划 / 工单

必需字段：成品号、数量、需求/完工日期。可选：工单号、产线、客户、客户等级、日罚款。

```csv
编号,成品,数量,完工日期,产线,客户,客户等级,日罚款
WO-001,FG-001,40,2026/08/10,L1,示例客户,1,1800
```

可以选择本地 CSV，也可以直接粘贴。每次点击“识别列名并加入数据”只追加当前页签的数据。
建议在导错时重置页面后重新开始，v0.1 不提供逐批撤销。

## 5. 脏数据容忍

解析器会模糊匹配常见中英文列名：

- `物料编码 / 料号 / material / item`
- `数量 / 单耗 / qty / quantity`
- `到货日期 / 交期 / due date`
- `产线 / 线体 / line`

日期支持 `2026-08-19`、`2026/8/19`、`2026年8月19日` 和 Excel 日期序号。数量支持
`1,200 pcs`、`620件`、`12 公斤`、`3.5K`。无法识别的坏行会被跳过并在“解析警告”
明确列出；系统不会悄悄把坏值当作 0。

## 6. 理解净算与传播

1. 从每张成品工单递归展开 BOM；
2. 同一组件从多条分支到达时累计用量；
3. 损耗率乘入下层需求；
4. 遇到循环引用时切断该分支并记录循环路径，避免死循环；
5. 现货扣除预留后形成第一批可用量；
6. 每张采购到货形成一个带日期的批次；
7. 按“客户等级 + 日罚款”或“原交期优先”顺序分配；
8. 工单拿到的最晚物料批次决定预计完工日；没有覆盖的数量进入净缺口。

它是快速冲击推演，不是精细有限产能排程。结果需要计划、采购与现场负责人确认。

## 7. 参数化 Playbook

五类动作都来自可枚举的现实行动空间：

- **催交期**：算出首批需要拉进几天、最低先到数量；
- **挪料保单**：显示先保护多少张高代价订单；
- **提前改承诺**：按日罚款与延期量估计代价；
- **替代料 / 改方案**：由人输入测试天数与成本，系统只判断窗口是否还活着；
- **提良率 / 降损耗**：比较覆盖缺口所需提升与现场可做到的提升。

“替代料测试成本、罚款条款、现场可提良率”是机器不知道的参数，必须显式由人输入。
工具不假装全知。

## 8. 指令卡与导出

七张指令卡分别给：

- 采购：催哪张采购单、当前日期、目标日期、最低数量；
- 产线：哪些线换排、冻结哪些工单、优先保哪些工单；
- 仓库：停止自由领料、实盘、预留和跨库位调拨；
- 计划：按什么规则重排、哪些工单需要改承诺、何时重新推演；
- 研发：替代料验证窗、预算上限、测试矩阵与研发 / 质量联合放行；
- 销售：按客户和罚则重谈交期，且不得承诺早于计划预计完工日；
- 物流：把供应商齐套、分批提货、运输、到厂、检验放行与入库串成里程碑。

“复制为 agent prompt”得到自然语言工单；花括号按钮得到结构化 JSON。页面左下“导出完整
事件 JSON”包含分析结果和七张指令，不包含原始 CSV 内容。

## 9. 隐私、可靠性与限制

- 浏览器本地计算，不上传、不持久化；
- 运行时零 LLM，数字不由语言模型生成；
- 模板文本只引用已经计算出的料号、日期、数量、工单和产线；
- 内置合成数据不含真实公司资料；
- v0.1 不做时间序列预测、精细产能排程、HR 排班、多工厂；
- 结果用于快速推演和跨部门对齐，不替代 ERP/MES、采购承诺或现场盘点。

## 10. 评委建议体验路径（2 分钟）

1. 首页看“确定性规则 + 零上传”定位（15 秒）；
2. 一键演示，读顶部四个事件数字（15 秒）；
3. 拖动冲击图，看物料如何打到客户（20 秒）；
4. 把首批到货从 8 月 19 日改成 8 月 5 日（20 秒）；
5. 修改替代料天数/成本或切换分配规则（20 秒）；
6. 复制采购 prompt 和计划 JSON（20 秒）；
7. 导出完整事件 JSON（10 秒）。
